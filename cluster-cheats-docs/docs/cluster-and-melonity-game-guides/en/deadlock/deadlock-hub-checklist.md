# Deadlock Hub Checklist

A broad Deadlock hub is a map, not proof that every listed feature is current. Start by writing the decision you need to make: define a term, check a source, compare claims, or decide when to stop.

![Deadlock hero artwork from the source site](https://deadlockhacks.com/images/deadlock-hero.webp)

The [Deadlock cheat guide](https://deadlockhacks.com/) is most useful when it leads to a narrower question. Check whether names stay consistent from the hub to the detail page, whether support and documentation remain on the same domain, and whether an editorial explanation is clearly separated from a commercial statement.

## Five quick checks

- Write the reader decision in one sentence.
- Follow one related link and compare its title, domain, and terminology with the hub.
- Look for a date, version note, or changelog; a current-looking design is not a date.
- Treat screenshots as examples of one captured state, not proof of universal compatibility.
- Record one unresolved question and stop if the answer would change your decision.

A hub can show categories, public positioning, and navigation. It cannot prove permanent compatibility, zero account risk, or a future update outcome. Keep that boundary visible while reading.

## FAQ

### Is a large feature list enough?

No. Use it to form questions, then verify scope, source continuity, maintenance, and the risks the page cannot remove.

### Can one screenshot prove compatibility everywhere?

No. It proves only what is visible under the captured conditions.

### When should I walk away?

Walk away when the source identity changes, a dated clip is presented as current status, or missing documentation is treated as irrelevant.
